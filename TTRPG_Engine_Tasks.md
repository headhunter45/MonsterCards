## APP-01: Scaffold new `:ttrpg-engine` module
**Status:** Ready
**Details:**
Create a clean Android Application module named `:ttrpg-engine`. Ensure it targets the same SDK versions as the primary `MonsterCards` app but maintains its own separate `AndroidManifest.xml`, resources, and launch activities. Add dependencies for Room, OkHttp, Handlebars.java, and RxJava.

## APP-02: Implement Room Database for Document Storage
**Status:** Ready
**Details:**
Create the initial SQLite database schema using Room.
- **Table 1 (`rulesets`)**: Columns for `ruleset_id` (PK), `base_url`, `name`, `version`, `author`, `last_sync_timestamp`.
- **Table 2 (`entities`)**: Columns for `uuid` (PK), `ruleset_id` (FK), `entity_type`, `display_name`, and `json_payload` (String).
Write DAOs to insert rulesets and entities, and to query entities by `ruleset_id` and `entity_type`.

## APP-03: Build Deep Linking & NFC Intent Handlers
**Status:** Ready
**Details:**
Configure `AndroidManifest.xml` to intercept both custom URI schemes (`ttrpg://`) and standard HTTPS App Links (`https://ttrpgwith.me/import/...`) as well as `NDEF_DISCOVERED` intents for NFC tags. Build a routing Activity that parses the incoming URL to extract the `base_url`, `ruleset_id`, and `entity_id`.

## APP-04: Implement Ruleset ZIP Downloader & Extractor
**Status:** Ready
**Details:**
Create an RxJava-based background service (similar to `GitRepoImporterService`) that downloads a ZIP archive from `[base_url]/v1/[ruleset_id].zip`. Safely extract this ZIP file into the app's internal protected storage (`context.getFilesDir() + "/rulesets/[ruleset_id]/"`). Include logic to delete old extractions if updating a ruleset.

## APP-05: Build Ruleset Manifest Parser
**Status:** Ready
**Details:**
After a ruleset ZIP is downloaded and extracted, read the `manifest.json` file. Parse its contents using Gson to extract the metadata (name, version) and insert/update the record in the `rulesets` Room table, officially registering the ruleset as available for rendering.

## APP-06: Integrate Handlebars.java for Native Templating
**Status:** Ready
**Details:**
Integrate the [Handlebars.java](https://github.com/jknack/handlebars.java) library. Create a service that takes an entity's `json_payload` (parsed to a Map/JsonObject) and merges it with the corresponding HTML template file found in the extracted `rulesets/[ruleset_id]/templates/` directory.

## APP-07: Create Secure WebView rendering fragment
**Status:** Ready
**Details:**
Build an Android Fragment containing a `WebView`. Apply strict security settings: disable File/Content access, enable Javascript. Inject a strict Content Security Policy (CSP) `<meta>` tag into the HTML string generated by APP-06 before calling `webView.loadDataWithBaseURL()`.

## APP-08: Implement Local Asset Interceptor for WebView
**Status:** Ready
**Details:**
Create a custom `WebViewClient` and override `shouldInterceptRequest`. Catch requests made by the HTML for CSS/JS files (e.g., `<link href="style.css">`) and manually load them from the internal `rulesets/[ruleset_id]/templates/` directory as `WebResourceResponse` streams. Block all external HTTP requests.

## APP-09: Build Entity List/Library UI
**Status:** Ready
**Details:**
Create a standard `RecyclerView` that queries the `entities` Room table. Group entities by `ruleset_id` and `entity_type` (using the `display_name` for the rows). Tapping a row should navigate to the Secure WebView Fragment (APP-07) to render the entity.

## APP-10: Implement JS/Native Telemetry Bridge
**Status:** Planning
**Details:**
Use `@JavascriptInterface` to expose a limited Android object to the WebView. Allow minigame/template JS to call `window.AndroidApp.postEvent("unlocked_secret")`. In the Android layer, queue these events and transmit them back to the API server (`[base_url]/v1/telemetry`) securely.

## API-01: Define Server Zip Generation Endpoint
**Status:** Ready
**Details:**
*(CharacterDataFiles Server Requirement)*
The API server providing the rulesets must expose a `GET /v1/[ruleset_id].zip` endpoint. This endpoint must dynamically or statically serve a zipped archive containing the `manifest.json` and the full `/templates` directory for the requested ruleset.

## API-02: Host `assetlinks.json` & `apple-app-site-association`
**Status:** Planning
**Details:**
*(CharacterDataFiles Server Requirement)*
To support background NFC scanning on iOS and seamless App Links on Android, the API provider's web root (`https://ttrpgwith.me/.well-known/`) must host the cryptographic verification files binding the domain to the Android and iOS app application IDs.

## API-03: Define Server Telemetry/Tracking Endpoints
**Status:** Planning
**Details:**
*(CharacterDataFiles Server Requirement)*
To support the minigame unlock requirements, the API must expose an authenticated or session-based endpoint (e.g., `POST /v1/telemetry`) to receive and process interaction events triggered by the mobile application's native bridge.
